# Климатические данные населённых пунктов

> **Стартовая мастер-таблица.** Этот справочник является **базой стартового
> наполнения** для калькулятора НВФ и **требует дальнейшей сверки по актуальным
> сводам правил**. Не использовать значения из этого файла для выпуска
> расчётно-конструкторской документации без проверки.

## Назначение

При выборе пользователем населённого пункта в калькуляторе фасадных систем
интерфейс должен подтягивать нормативные параметры района строительства:

- снеговой район и нормативное значение `Sg`, кПа;
- ветровой район и нормативное давление `w0`, кПа;
- гололёдный район и толщину стенки гололёда, мм;
- сейсмичность площадки, баллы;
- статус достоверности каждого параметра и общий статус записи;
- источник данных.

## Структура файлов

```

docs/
```

Ручные правки рекомендуется делать в `scripts/build_data.py` или в Excel
с последующим переносом в Python-источник, после чего пересобирать оба формата:

```bash
python3 scripts/build_data.py
```

## Правила заполнения

1. **Не выдумывать значения.** Если для параметра нет проверенного значения,
   ставится `null` и статус `requires_verification`. **Запрещено** использовать
   `0` как заглушку.
2. Для значений из приложения К СП 20.13330.2016 указывается статус
   `from_sp20_appendix_k`.
3. После ручной сверки инженером статус параметра меняется на `verified`,
   при этом следует указать дату/инициалы в `comment`.
4. Сводный `data_status`:
   - `verified` — все четыре блока (snow, wind, ice, seismic) имеют статус
     `verified` либо `not_applicable`;
   - `partial` — заполнена только часть параметров;
   - `requires_verification` — запись только что создана и требует проверки.
5. Идентификатор `id` — строго латиница в формате slug, без пробелов и
   диакритики (`saint_petersburg`, не `Санкт-Петербург`).

## Контрольные города

Для регрессионной проверки нормативные значения должны проверяться вручную
для следующих 15 городов:

Москва, Санкт-Петербург, Челябинск, Екатеринбург, Казань, Новосибирск,
Краснодар, Пермь, Уфа, Самара, Ростов-на-Дону, Тюмень, Омск, Владивосток,
Якутск.

Эти города выведены отдельно на лист `03_control_checks`.

## Расширенная схема (СП 22 + СП 131)

Помимо базовых нагрузок, для записей, обогащённых через ese.pro,
в JSON добавляются опциональные поля:

- `frostDepth` — нормативная глубина сезонного промерзания `dfn`, м
  (суглинки/глина, супесь и пески мелкие, пески крупные, крупнообломочные грунты);
- `coldPeriod` — 19 параметров холодного периода (температура холодных
  суток/пятидневки с обеспеченностью 0.92/0.98, влажность, осадки, скорость
  ветра, продолжительность периодов ± …);
- `warmPeriod` — 12 параметров тёплого периода (барометрическое давление,
  температура с обеспеченностью 0.95/0.99, абсолютный максимум, осадки
  апрель–октябрь, влажность, ветер июль и др.);
- `monthlyTemps` — среднемесячные температуры воздуха за 12 месяцев +
  среднегодовая, °C.

Эти поля обязательны только для записей со статусом `verified` и появляются
по мере сбора данных парсером `scripts/scrape_ese.py`.

См. `src/types/climate.ts` — интерфейсы `FrostDepthData`, `ColdClimateData`,
`WarmClimateData`, `MonthlyTempsData`.

## Сбор данных через ese.pro

Скрипт `scripts/scrape_ese.py` использует Playwright для обхода всех
населённых пунктов из `settlements-climate.json`, ввода имени в калькулятор
ese.pro и извлечения всех видимых параметров:

```bash
# установка
pip install playwright openpyxl
playwright install chromium

# полный проход
python3 scripts/scrape_ese.py

# выборочный проход по конкретным идентификаторам
python3 scripts/scrape_ese.py --ids moscow,saint_petersburg,chelyabinsk

# сборка JSON/XLSX с учётом собранных данных
python3 scripts/build_data.py
```

Парсер идемпотентен и возобновляем: результаты сохраняются в `outputs/ese-data.json`,
уже собранные города пропускаются.
